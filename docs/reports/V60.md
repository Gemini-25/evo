# v6.0 보고: 빠르게 (결과는 v3.1과 비트 동일, 관전 방식 「학습 먼저」)

## 요약

- **무엇**: v6 「속도와 자라는 뇌」의 첫 출시입니다(명세 부록 A91~A105, 설계 `v6/design.md`). 학습 결과를 한 비트도 바꾸지 않고 같은 계산을
  더 빨리 하게 했고, 관전할 때 학습이 재생을 기다리지 않는 관전 방식 「학습 먼저」를 더해 기본으로 두었습니다. 환경 파일, 실행 폴더, 체크포인트,
  재현 묶음, 학습 방법은 바꾸지 않았고(v6.0으로 만든 실행을 v3.1이 그대로 이어 감), 프로세스 사이 메시지는 칸만 더했습니다(화면↔학습: `mode`
  명령의 `pace`, 세대 메시지의 `waited`. 워커 작업: `Task.window`, 없으면 `EVAL_WINDOW`). 새 실행 의존성도 없습니다(`uv.lock` 차이는 evolab 버전
  줄뿐). 버전은 6.0.0이고 커밋은 1e59b26입니다.
  - **런타임**(`world/physics2d/episode.py`): 물체 상태 읽기·힘·속도·모터 쓰기를 pymunk가 감싸는 C 함수로 바로, 둘째 스텝부터 `cpSpaceStep`을 바로,
    몸 상태 값·센서는 만들 때 고른 항목별 함수로, 사건은 한 루프로, 접촉은 모양별 맞음 기억으로, 공기역학 상수는 미리 펼쳐서, 행동은 묶음마다
    `tolist()` 한 번 뒤 새 `step_values(list)`로. 식과 순서는 그대로라 결과가 바이트까지 같습니다.
  - **세계 만들기**: 레이 필터를 모양마다 한 번만 쓰고 같은 꼬리표 묶음을 나눠 씁니다(설계 4.6, 묶음 R). 측정 단계에서 바퀴 고르는 언덕차 bench
    장면이 기준을 0.003 넘어, 수리 단계에서 설계 4.6·D13 밖으로 언덕·높이 지도 생성기가 만든 점의 작은 캐시(프로세스마다 8벌)와 마찰·레이 필터의
    C 쓰기를 더했습니다.
  - **평가 창·GC**(`engine/evaluate.py`, `engine/pool.py`): 한 평가가 살아 있는 에피소드를 12개(`EVAL_WINDOW`)만 두고 끝난 자리를 다음 쌍으로 바로
    채웁니다. 워커는 첫 작업 뒤 GC를 한 번 얼립니다(`WORKER_GC_FREEZE`).
  - **bench·자체 점검**: `evolab bench`의 단일 코어 줄이 「창 12」로 재고, 「평가 창」·「관전 재생 길이」·「pymunk C 함수 바로 부르기」 줄이 생겼습니다.
    자체 점검에 「빠른 계산 길」(내장 예제 6개를 C 길과 보통 길로 평가해 바이트 비교)이 더해져 13개가 됐습니다.
  - **관전 방식**: 실험실 「보기」 묶음에 「관전 방식」 칸(「학습 먼저 (새 세대만 보기)」 / 「세대마다 다 보기 (학습이 기다림)」). 사용자가 설계 권장을

- **평가 창·GC·bench** (`engine/evaluate.py`, `pool.py`, `commands.py`, 묶음 E; 되돌린 항목 없음)
  - `EVAL_WINDOW: Final[int] = 12`, `evaluate(..., window=None)`(1 미만 `ValueError`, 정수가 아니면 `TypeError`). 슬롯은 0..L−1에 모여 있고 신경망 가중치는
    슬롯 배열이라 다시 채운 슬롯을 복사 없이 봅니다. 끝난 슬롯은 그 자리에서 결과·궤적·관찰을 넘기고 Episode를 놓습니다. 조립 실패는 창 안에서
    처리하고(`_only_body_failures` → `_check_body_failure`, 같은 쌍의 같은 오류), `step_values`가 없는 Episode면 `step()`을 부릅니다(오라클 Episode로 시험).
    관찰 비우기 주기, `nn_seconds`·`sim_seconds`의 뜻, `replay.py`가 쓰는 `_Recorder`는 그대로입니다.
  - `WORKER_GC_FREEZE: Final[bool] = True`: 워커가 첫 결과를 보낸 뒤 `task`·`msg`를 놓고 `gc.collect(); gc.freeze()` 한 번. 부모가 띄울 때 깃발 값을
