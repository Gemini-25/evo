# v2.1 보고: 몸 구조 진화 (바퀴 고르는 언덕차)

## 요약

- **기능**: 몸의 부품이 진화로 생기고 없어집니다. 에이전트 물체마다 「있음」 칸(`exists`)을 두고, 그 값이 0.5보다 크면 물체를 만듭니다.
  유전자 길이와 뇌 입출력 수는 실행 내내 같아서 학습 방법, 저장, 그래프가 그대로 돕니다.
  - **내장 예제 「바퀴 고르는 언덕차」**: 바퀴 자리 네 곳 중 어디에 몇 개를 달지, 크기와 차체 모양이 함께 진화합니다. 모터 힘 600N·m은 달린
    바퀴가 나눠 씁니다. 처음 몸은 일부러 뒤 바퀴 하나뿐입니다.
  - **학습 방법**: 유전 알고리즘·담금질에 구조 뒤집기 돌연변이를 더했습니다(구조 환경의 새 실행 0.05).
  - **에디터**: 「있음」 진화 체크, 「구조」 탭, 「배열로 늘리기」, 없는 부품 점선 보기.
  - **실험실**: 대시보드 「몸 구조」 타일(세대별 구조 비율, 보는 세대 챔피언의 몸), 클릭 검사 「(없음)」.
- **형식**: 환경 파일 형식 3. `exists`를 쓰지 않는 파일은 v2.0이 쓴 글·해시 그대로이고 결과도 같습니다. v2.0 프로그램은 형식 3 파일을
  「… (파일 버전 3) …」으로 거부합니다.
- **완료 기준**: 아래 「완료 기준 점검」 표에 있습니다.
  - 바퀴 고르는 언덕차: 구조 진화 255.12·257.34·252.51m(중앙값 255.12m)로 바퀴 1개 고정 221.16m의 1.154배, 2개 고정 257.89m의
    0.989배이고, 세 시드 모두 구조가 바뀌었습니다. 충족입니다(기준 1.1배·0.95배·두 시드).
  - 구조 뒤집기(M12): GA는 충족했습니다(판정 중앙값 33.91 → 187.66m, 구조가 바뀐 시드 1 → 3). **담금질은 시드 1·2·3의 판정 중앙값이
    253.03 → 248.99m(−1.6%)로 「p = 0보다 낮지 않음」을 글자 그대로는 못 맞췄습니다.** 시드 9개로는 238.58 → 248.99m이고 9개 중 7개에서
    나았습니다. 되돌릴 지점 6은 GA만 대상이라 새 실행 기본 0.05를 두 방법 모두 그대로 두었습니다.
  - 「몸 구조」 타일(M13): 세대 도착 때 갱신 + 그리기가 중앙값·최악 모두 10ms 이하입니다(측정 고침 뒤, 읽은 기록을 먼저 한 번 그리는 새

## 바뀐 것

- **환경 파일** (`spec/model.py`, `io.py`, `compiled.py`, `symbols.py`, 새 `spec/structure.py`)
  - `Body.exists`(형식 3, 변환 2 → 3은 사전 그대로). 수식은 「구조」 단계라 `p.*`와 상수만 씁니다(`r.*`·`gen.*`·시간은 오류).
  - `spec/structure.py`: 런타임·검사·화면·에디터가 함께 쓰는 순수 함수(`root_body`, `connected`, `absent_from`, `optional_bodies`, `present`,
    `structure_key`, `param_values` 등). 이어짐 규칙: `exists` ≤ 0.5인 물체와, 그것들을 빼면 관절로 몸통에 이어지지 않게 되는 에이전트 물체가
    없는 물체입니다. 처음부터 몸통과 이어지지 않은 물체는 건드리지 않습니다.
  - 검사: 세계 물체의 `exists`, 몸통(첫 에이전트 물체)의 `exists`, 없어질 수 있는 물체를 사건·점수 블록·점수 수식·체크포인트·목표 센서의
    목표·`dist`·`inside`·몸 상태 이름에서 쓰면 오류입니다(어느 자리인지 이름을 붙임). 접촉, 접촉 시간 블록, 그 물체에 단 센서는 됩니다.
    검토 뒤 범위 가운데가 0.5가 아닌 있음 몸 수치를 알리는 「안내」(`SPEC_EXISTS_FLIP_RANGE`)를 더했습니다.

    없는 물체·관절의 센서는 모두 0(레이 포함), 없는 물체와의 접촉은 거짓입니다.
  - 읽기 전용 `Episode.absent`, `absent_joints`, `dead_channels`(검토 뒤).

## 결정성과 호환

자동 테스트로 지키는 것(`tests/test_structure.py`, `test_structure_runtime.py`, `test_structure_learners.py`, `test_structure_tile.py`,

  단위로 같음(T3 추가). `exists` 하나만 쓰면 형식 3이고 지우면 글이 돌아옴(T59). v1 파일은 T1·T2 그대로.

  어느 플랫폼에서나). 점프·글라이더 결과가 v2.0 코드로 만든 기준 자료와 같음(T62, 같은 플랫폼). v1 결과는 T29.

  p = 0.05 이어하기 비트 동일. 학습 중 있음 수식을 고친 뒤의 체크포인트에서 이어 가도 비트 동일(검토 뒤).

### M12 구조 뒤집기 (목표: p = 0.05에서 구조가 바뀐 시드 ≥ 2, 판정 중앙값이 p = 0보다 낮지 않음)

절차: M11과 같은 명령에 `--method ga|sa --structure-flip 0|0.05`, 워커 3, `--no-restart`. GA는 새 실행 기본 개체 64(명령줄·실험실·반복 실행

### M13 「몸 구조」 타일 (목표: 세대 도착 때 갱신 + 그리기 ≤ 10ms, v1.2 이벤트 루프 목표 그대로)

**(가) 갱신 + 그리기**: 가짜 750세대 바퀴 실행(개체 32)을 `load_history`로 읽고, 세대가 하나씩 도착할 때 `refresh + prepare_paint + repaint`를
쟀습니다(오프스크린).

측정 고침에서 쌓은 영역 일곱 개를 한 덩어리(`_StackArea`, 다각형을 자료가 바뀔 때 한 번 만들고 그릴 때는 채우기만)로 바꾸고, 챔피언 몸 배경
작업이 세 단계 하나하나 앞에서(처음만이 아니라) 화면이 한가해지기를 기다리게 했습니다. 옛 그림과 새 그림은 픽셀이 100% 같았습니다(테스트
기준 99.5%).

또 느린 테스트의 절차를 바꿨습니다. `dash.flush()`는 그리지 않고 갱신만 해서, 옛 절차의 첫 「도착」에는 750세대 기록 전체를 처음 그리는 일이
들어 있었습니다(실제 펌프는 그 상태를 그리지 않은 채 두지 않음). 새 절차는 읽은 기록을 먼저 한 번 그리고 그 시간을 따로 출력한 뒤 도착을

## 설계와 달라진 것

- **있음 유전자를 좁힘**: `on_genes`는 설계 4.12·7.3의 조건(`exists`가 정확히 `=p.<id>`, 진화)에 「그 몸 수치 범위의 가운데가 0.5」를
  더했습니다. 설계의 뒤집기(부호 바꾸기)는 문턱이 유전자 0에 있을 때만 구조를 바꾸기 때문입니다(범위 0..2면 −0.3 → +0.5가 둘 다 있음).
  에디터가 만드는 `_on`(0..1)과 내장 예제는 해당됩니다. 검토 뒤 이런 칸을 조용히 빼지 않고 검사 「안내」(`SPEC_EXISTS_FLIP_RANGE`)와 실험실·
  명령줄 안내(`LAB_STRUCTURE_RANGE`)로 알립니다.
- **담금질 기본값**: 설계 9.3 기준 3은 M12를 못 맞추면 되돌릴 지점 6으로 보내지만, 되돌릴 지점 6은 GA 판정 중앙값이 낮아질 때만입니다. GA가
  충족해 담금질도 0.05로 두었습니다(위 M12).
- **검사**
  - 접촉 시간 블록은 없어질 수 있는 물체에 써도 됩니다(접촉 재기라서). 자기 물체가 없어질 수 있는 목표 센서도 되고 0을 읽습니다. 목표 센서의
    `target`이 없어질 수 있는 물체면 오류입니다.
  - 체크포인트 기본 물체(차량 구동기 물체를 따름)가 없어질 수 있으면 오류입니다. 몸통의 `exists`는 한 번만 알리고 그 뒤 참조 검사에서는 몸통을
    늘 있는 것으로 봅니다.
- **런타임**: 남은 물체를 몸통 먼저로 다시 줄 세우지 않고 선언 순서를 지킵니다(v1 궤적 순서가 바뀌지 않게, 몸통이 늘 있어 첫 에이전트 물체는
  같음). 죽은 채널은 실제 출력뿐 아니라 명령도 0이라 부드러움 블록이 그 채널을 보지 않습니다. 더한 것: `Episode.absent_joints`,
  `dead_channels`, 레이 센서마다 자리를 남기는 `_ray_views`.
- **학습 방법**
  - `on_genes`는 같음 비교에서 빠집니다(`from_dict(to_dict(x)) == x` 유지). 학습 방법 상태는 v2.0과 똑같이 돌 때(p = 0이거나 있음 유전자가
    없음) 구조 키를 쓰지 않습니다. `TrainConfig.to_dict`는 `ga_structure_flip`·`sa_structure_flip`을 늘 씁니다(v2.0은 모르는 키를 버림, 확인함).
  - `--structure-flip`은 GA·담금질 확률을 함께 정합니다. T67은 정답 해시를 박지 않고 테스트 때 v2.0 커밋 코드를 꺼내 비교합니다.
  - 학습 중 있음 수식을 고치면 GA·담금질의 뒤집을 유전자를 새 배치에 맞춥니다(`set_structure`, 설계에 없던 규칙, 검토 뒤).
- **내장 예제**: `wheels.evoenv`는 `dump_env`가 아니라 언덕차와 같은 모양으로 손으로 정리했습니다(내용은 테스트가 고정). 설계 4.14에 없던 기본
  보기 (−4, −2)~(10, 5)를 더했고, D25대로 직접 조종·관전·경주·영상의 처음 카메라도 됩니다(해시 그대로). 자체 점검은 처음 몸이 곧 뒤집히므로
  바퀴 1·4를 단 몸으로 두 번 돌립니다.
- **에디터**
  - 「배열로 늘리기」는 물체와 함께 사라질 부품(이어짐 규칙)까지 관절과 함께 복제합니다(허벅지만 복제하면 정강이 하나에 허벅지가 여럿 매달림).
  - 사본 이름은 끝 번호를 올리고(`wheel1` → `wheel2`, 이름표 「바퀴1 축」 → 「바퀴2 축」), 번호가 차 있으면 가장 큰 번호 다음부터(검토 뒤). 번호가
    없으면 설계대로 `<id>2`, 이름표는 끝에 「 2」.
  - 「개수를 몸 수치 하나로」의 몸 수치는 `<id>_count`가 아니라 `<줄기>_count`(`wheel1` → `wheel_count`)이고, 원본도 `> 0.5`를 받으며, 개수를
    고르면 늘 진화합니다.
  - 직선 배치는 원본을 움직이지 않습니다(출발점이 원본 자리). 거울은 늘 2개이고 모양·고정점·쉬는 각도·관절 제한·추진기와 점프 방향·레이 가운데를
    뒤집습니다. 수식 칸은 수식으로 남습니다(`=-p.half` → `=p.half`). 뇌 입력·출력이 목록이면 사본 채널을 뒤에 붙입니다. 몸통은 늘릴 수 없습니다.
  - 있음 진화를 켜고 늘리면 사본 수식 안의 원본 있음 몸 수치를 사본 것으로 바꾸고, 다른 몸 수치를 원본과 함께 쓴다고 상태 줄에 알립니다(검토 뒤,
    설계 5.1은 부품 id만 바꾸라고 함).
  - 「없는 부품도 보기」는 기본 켬이고 구조 탭에만 있습니다(기존 테스트가 「보기」 메뉴 항목을 정확히 확인함). 숨은 부품을 밖에서 고르면 다시
    켭니다(검토 뒤).
  - 있음 진화를 끌 때 그 몸 수치를 다른 수식이 쓰면(바퀴 고르는 언덕차의 모터 힘) 몸 수치는 두고 진화만 끕니다. 구조 탭의 진화 칸도 누를 수
    있고, 개수 몸 수치로 정해지는 줄은 켜진 채 잠깁니다(검토 뒤).
- **화면**
  - 타일에 환경 버전은 `view.py`가 `set_env_versions`로 넘깁니다(`WatchMeta`에 환경이 없음). 없는 부품의 점선 윤곽은 `exists`를 뺀 사본으로
    만든 둘째 Episode에서 몸통 기준으로 가져옵니다.
  - 클릭 검사는 `Episode.absent` 대신 `structure.present`로 셉니다(`engine/replay.py`의 재생 자료에 없음, 결과가 같음을 테스트). 줄은
    `c2 (없음)`처럼 이름 뒤에 붙입니다(1280×800에서 패널이 약 13자라 줄 끝 표시가 보이지 않았음).
  - 많은 6개는 세대별 비율의 합으로 고르고(대표만 있는 세대를 덜 세지 않게), 쌓는 순서는 부품 수입니다. 같은 개수의 구조가 「기타」 안에라도
    있으면 이름을 붙입니다. 칸 격자는 끕니다(그리기 비용). 구조마다 색 자리를 유지합니다(검토 뒤).
    200세대까지는 세대마다 한 칸(계단)으로, 넘으면 영역으로 그리고, 세대가 그림 가로 픽셀보다 많으면 이웃 세대를 묶어 평균합니다.
  - 쌓은 영역을 한 덩어리로 그리고, 챔피언 몸 배경 작업은 세 단계 하나하나 앞에서(처음만이 아니라) 화면이 한가해지기를 기다립니다(측정
    고침). 배경 작업 기다리기는 `Dashboard.shutdown`이 합니다.
