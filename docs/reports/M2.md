## 바뀐 것

- 신경망·유전자: 묶음 순전파(층마다 (N,1,입력)×(N,입력,출력) 행렬 곱, 행마다 독립), 몸 수치 + 뇌 유전자 배치
- CMA-ES(pycma 감싸기): 전용 난수, 출력 끔, 경계 처리, sep-CMA 전환 차원 설정, IPOP 선택, 비트 동일 이어하기
- 시드 공간: 학습 `[0, 실행 시드, 세대, 시험]`, 검증 `[1, k]`, 비교 `[2, k]`, 판정 `[3, k]`
- 워커 풀: 상주 spawn 워커, 동적 분배, 워커가 죽으면 다시 띄워 같은 작업 재평가, 환경 버전별 컴파일 캐시,
  물리 코어 − 1, 윈도우에서 낮은 우선순위, BLAS 1스레드. 워커마다 작업·결과 파이프 + 보내는 스레드
  (윈도우에서 죽은 워커에 보내다 멈추는 문제를 고친 구조, 아래 "CI" 참고)
- Trainer: 공통 시드 세대, 학습 시험 1000회마다 검증 세트 20개로 챔피언 선정, 정지 조건(세대·시험·시간·목표·정체),
  통계(stats.csv), 세대 대표·챔피언 저장, 10세대마다 체크포인트, 이어하기
- 실행 저장소: run.json, 환경 버전 사본, stats.csv(엑셀이 잠가도 학습 계속), events.jsonl, 체크포인트 보관 정책
- 명령: `evolab train`(--resume, 정지 조건, --diagonal-threshold, --ipop), `evolab bench`, `evolab judge`

## 실행 명령

```powershell
# exe(CI 산출물 evolab-windows)를 푼 폴더에서
.\evolab-cli.exe train _internal\environments\lander.evoenv --max-time 900     # 15분 학습
.\evolab-cli.exe judge "문서\진화실험실\runs\<실행 폴더>"                         # 판정 시드 100개로 챔피언 평가
.\evolab-cli.exe train --resume "문서\진화실험실\runs\<실행 폴더>" --max-time 1800  # 이어하기
.\evolab-cli.exe bench _internal\environments\lander.evoenv                       # 성능 측정
```

개발 환경에서는 `uv run evolab train environments/lander.evoenv --max-time 900` 처럼 씁니다.

## 직접 확인할 항목

1. `train ... --max-time 900`으로 15분 학습하고 `judge`로 판정하면 성공률이 80% 이상인지(아래 측정은 리눅스 4코어)
2. 학습 중 Ctrl+C 한 번이면 이번 세대를 마치고 체크포인트를 남기고 끝나는지, `--resume`으로 이어지는지
3. 학습 중 stats.csv를 엑셀로 열어도 학습이 계속되는지(닫으면 밀린 줄이 들어옴)
4. `bench` 수치가 아래와 비슷한지(노트북 전원 연결·최고 성능 모드 권장)

## 테스트

- 빠른 테스트 전체 통과(리눅스). M2 관련: 워커 0·1·3개 결과 비트 동일, 끊고 이어하기가 끊지 않은 실행과 같음,
  비정상 종료 뒤 이어하기에서 줄 중복 없음, 죽은 워커 대체, 환경 오류 → PoolError, 정지 조건, 명령줄.
- 느린 학습 테스트(`pytest -m slow tests/test_slow_lander.py`): 위 표의 3개 시드 측정이 그것입니다.

## CI (윈도우)

- M2 커밋의 CI는 테스트 894개가 통과한 뒤 pytest가 끝나지 않아 45분 제한에 걸렸습니다. 원인: 죽은 워커의 받은편지함
  Queue에 넣은 작업을 Queue의 보내기 스레드가 아무도 읽지 않는 파이프에 쓰다 멈추고, 종료 때 그 스레드를 기다림.
  리눅스에서도 큰 작업으로 재현해 고쳤고(워커마다 파이프), 그다음 CI에서 윈도우는 죽은 워커의 파이프에 직접 쓰는 것도
  끝나지 않는다는 것이 드러나(connection.py:293) 보내기를 스레드로 옮기고 워커가 죽으면 파이프를 닫게 고쳤습니다.
  회귀 테스트 포함. 최신 CI 결과는 M3 보고서에 적습니다.
