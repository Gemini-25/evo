# v1.1 보고: 학습 안정성 (자동 재시작, 예선)

## 요약

- **기능**: 자동 재시작과 예선을 만들었습니다. 학습 결과의 결정성과 v1.0 실행·재현 묶음 호환도 확인했습니다(아래 「결정성과 호환」).
- **기본값**: 미리 정한 실험(설계 16절)과 판단 규칙(R1~R4)대로 정했습니다.
  - 예선: 초반 검증 점수가 나중 결과를 예측하지 못했습니다. 그래서 끕니다.
  - 자동 재시작: 두 방식 모두 평균 판정 성공률을 낮췄습니다. 그래서 끕니다.
  - **새 실행의 기본은 v1.0과 같습니다.** 두 기능은 설정에서 켤 수 있게 남겼고, 학습 중에 켜고 끌 수도 있습니다.
- **완료 기준 1은 충족하지 못했습니다.** 착륙선 시드 1~14의 성공 시드 수가 v1.0보다 늘지 않았습니다. 이번 실험에서 성공 수를 가장
  크게 바꾼 것은 기능이 아니라 학습 시험 예산이었습니다. 기준선 성공 시드는 7만 회 5개, 9만 회 10개, 12만 회 11개였습니다.
- 시드 11처럼 끝까지 갇힌 실행을 처음 상태 재시작이 살린 사례도 있습니다(12만 회 17% → 94%). 다만 늦게 오르던 시드 6·8·9를
  더 크게 망쳤습니다. 계획 밖으로 P를 4만 회로 늘린 탐색(E6)도 해 봤습니다. 이때는 시드 11을 살릴 시간도 모자랐습니다.
  그래서 「오래 갇혀 있으면 재시작을 켜 보세요」를 선택 기능으로 남깁니다.

## 바뀐 것

- **자동 재시작**(엔진): 지금 학습 방법이 낸 검증 최고점이 그 학습 방법의 학습 시험 P회 동안 오르지 않으면, 세대 끝에 학습
  방법만 새로 만듭니다.
  - 새로 시작할 곳은 처음 상태, 챔피언에서, 번갈아 중 하나입니다. 새 시드를 쓰고 개체 수는 그대로입니다.
  - 챔피언, 통계, 사건 기록은 그대로 이어집니다.
  - 판단 입력이 검증 점수와 시험 수뿐입니다. 그래서 워커 수, 관전, 멈춤, 이어하기, 분기, 재현 묶음과 상관없이 같은 세대에서 일어납니다.
- **예선**(엔진): 실행 처음에 시드만 다른 학습 방법 K개를 차례로 B회씩 돌리고, 검증 최고점이 가장 높은 하나만 이어 갑니다(동점이면 앞 번호).
  - 비교·판정 세트는 선정에 쓰지 않습니다.
  - 예선 중에는 재시작과 정체 멈춤을 쉬고, 환경 교체를 받지 않습니다.
- **저장 형식**
  - 학습 방법 시드: 처음 학습 방법은 [4, s](v1.0과 같음), n번째로 만든 학습 방법은 [4, s, n]입니다.
  - 체크포인트 형식 2를 쓰고, 형식 1도 읽습니다.
  - 통계 열 7개를 더했습니다: `learner`, `learner_trials`, `learner_best`, `learner_stall`, `restarts`, `qualifying`, `switch`.
  - v1.0 실행은 옛 열 머리 그대로 이어 갑니다.
  - 재현 묶음은 원래 열 머리로 재현하고 엄격하게 비교합니다.
- **기본값 규칙**: 설정 클래스 기본값은 「끔」입니다. 새 실행(실험실, 명령줄 `train`, 반복 실행)만 권장값 `NEW_RUN_DEFAULTS`를 씁니다. 저장된 설정에 키가 없으면 끔입니다.
- **실험실**
  - 「학습 안정성」 설정 묶음
  - 상태 줄(지금 몇 번째 시도인지, 예선 중인지)과 바뀜 알림
  - 학습 중에 재시작을 켜고 끄기, 정체 판단 횟수와 새로 시작할 곳 바꾸기
- **대시보드**: 새로 시작·예선 세로선, 「지금 학습 방법 최고점」 선, 예선 띠.
- **반복 실행**: 「정체하면 새로 시작」을 고를 수 있습니다.
- **명령줄**
  - 새 플래그: `--restart N`, `--no-restart`, `--restart-from fresh|champion|alternate`, `--qualify K`, `--qualify-trials B`
  - 이어 갈 때 재시작 설정을 바꿀 수 있습니다.
  - 정체 판단 횟수가 검증 주기보다 짧으면 고칠 플래그를 알려 줍니다.

## 기본값을 정한 실험

### 방법

- 결정은 **학습 시험 예산**으로 합니다.
  - 결과가 워커 수와 상관없으므로 실험은 `--workers 0`으로 여러 개를 동시에 돌렸습니다. 4코어 컨테이너를 나눠 썼고 `nice -n 5`였습니다.
  - 7만·9만·12만 회 예산은 각각 438·563·750세대입니다(착륙선 개체 32, 시험 5회, 세대당 160회).
- 판정: `evolab judge RUN --generation G`, 판정 시드 100개(학습·검증·비교에 쓰지 않은 시드 공간 [3, k]). **80% 이상을 「성공」**으로 봅니다. 시드 100개 판정의 잡음은 ±3~5%p로 봅니다.
- 「15분 상당」: M2의 15분 실측 시험 수가 시드마다 달라서(시드 1 58,880 ~ 시드 11 120,160) 9만 회로 보고, 시드 11만 12만 회로 봅니다.
- 실험 코드는 고정 사본만 썼습니다.
  - 기준선 E1: v1.0 사본
  - 재시작 실험 E2·E6: v1.1 사본, `PYTHONPATH` 확인

### E6 탐색: 더 긴 P(40,000, fresh) — 미리 정한 계획 밖

- **실험 목적**: E2 뒤에 하나 더 돌렸습니다. P를 늘리면 늦게 오르는 시드는 덜 끊고, 갇힌 시드만 다시 시작할지 보려는 것입니다.
- **미리 적은 규칙(R5)**: 계획과 판단 규칙은 돌리기 전에 적어 두었습니다(`scratchpad/v11/an/r5.md`). 다음 두 조건을 모두 만족할 때만 P=40k를 기본으로 켭니다.
  - 14시드 12만 회 성공 수가 11개보다 많을 것
  - 트리거 시드의 평균이 기준선 이상일 것
- **트리거 시드**: P=40k 첫 재시작이 12만 회 안에서 일어나는 시드는 E1 통계로 계산하면 6·9·11 셋뿐입니다.

| 시드 | 재시작 (세대, 학습 시험 수) | 기준선 B (7만/9만/12만) | P=40k fresh |
| --- | --- | --- | --- |
| 6 | (407, 65,120) | 17/60/96 | 17/17/17 |
| 9 | (475, 76,000) | 18/18/77 | 18/18/18 |
| 11 | (513, 82,080) | 17/17/17 | 17/17/17 |

- 세 시드 모두 새 학습 방법이 12만 회까지 옛 챔피언을 넘지 못했습니다.
- 시드 6·9는 기준선이 그 뒤에 이룬 회복을 잃었습니다.
- 시드 11은 재시작이 늦어 남은 3만 8천 회로는 부족했습니다. P=20k에서는 같은 시드가 5만 8천 회 만에 94%가 됐습니다.
- R5 실패: 성공 수 9 < 11, 트리거 시드 평균 17.3 < 63.3. 재시작이 이르면 늦게 오르는 시드를 끊고, 늦으면 갇힌 시드를 살릴 시간이 없습니다. 이 착륙선 문제에서는 정체 길이 하나로 둘을 가를 P가 없었습니다.

- **R2**(켤 때의 방식): 트리거 시드 12만 회 평균은 champion 70.8, fresh 67.0입니다. 차이가 5%p 안이라 규칙대로 fresh로 둡니다. 사용자가 켤 때 기본으로 보이는 값입니다.
- **R3**(P): R1이 실패해 다룰 필요가 없습니다. 켤 때 보이는 값은 20,000 그대로입니다.
- **R4**(예선): G1이 실패해 끔(`qualify_entrants = 1`)입니다. 켤 때의 권장값은 규칙대로 12,000(결론 없음)입니다.

### 돌리지 않은 것과 이유

- **E2′(P 16k·24k 민감도)**: R3에만 쓰입니다. R1이 실패해 필요 없습니다.
- **E3(예선 출전자, 통과자 이어 가기, 실제 예선 확인)**: G1에서 멈췄습니다.
- **E4(트랙 자동차·언덕차·유전 알고리즘·담금질)와 E5(느린 테스트 45분)**: 새 실행 기본값이 v1.0과 같아졌습니다.
  - E0 ①·③이 「끈 v1.1 = v1.0」을 비트 단위로 보였습니다.
  - 그래서 1차 완료 기준 결과(트랙·언덕·착륙선 15분)가 그대로입니다. 다시 잴 것이 없습니다.
